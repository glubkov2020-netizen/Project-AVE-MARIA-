1.Общие сведения

Выработка ЭЭ по регионам РФ — аналитическая платформа для работы с данными о годовой выработке электроэнергии по субъектам Российской Федерации. Работает полностью в браузере, без серверной части, без передачи данных третьим лицам.

Назначение

  • Сбор и нормализация данных из разных источников (Минэнерго РФ, Росстат, СО ЕЭС, отчёты генерирующих компаний).
  • Построение официальных графиков и аналитических отчётов.
  • Статистический анализ: динамика, тренды, аномалии, структура, корреляции.
  • Продвинутая аналитика: кластеризация, PCA, непараметрические тесты.
  • Сценарное моделирование и прогнозирование.
  • Экспорт в 12 форматов, включая PDF, DOCX, XLSX, ZIP.

Ключевые принципы

  • Полностью клиентская работа. Все расчёты в браузере. Данные не отправляются на серверы.
  • Открытые формулы. Каждая метрика описана в Методике.
  • Честные данные. Прогнозы явно помечены, экстраполяции не выдаются за факты.
  • Официальное оформление. PDF/DOCX/HTML под документооборот организации.
  • Автосохранение в localStorage (при согласии пользователя).

2.Быстрый старт

2.1. Загрузка данных

Существует пять способов:

СпособКак
Seed-базаКнопка «Загрузить базу» (если рядом лежит data.js)
Вручную«+ Строка» в таблице ввода
Вставка CSV/JSONПоле «Вставка», кнопка «Проверить и добавить»
ФайлКнопка «Файл…» — .csv, .tsv, .json, .xlsx
ДемоКнопка «Демо» — синтетика 10 × 10

2.2. Проверка качества

Раздел «Паспорт данных» показывает:

  • процент заполнения матрицы регион × год;
  • пропущенные пары (визуальная матрица);
  • резкие скачки (более 50% год к году);
  • нули после положительных значений;
  • статусы «факт» для будущих лет.

2.3. Анализ

Разделы «Графики», «Сравнение», «Расчёты», «Тренды», «Продвинутая», «Структура», «Аномалии», «Тепловые карты», «Паспорт региона», «Сценарии» — каждый отвечает на свой вопрос. Подробнее см. раздел 5.

2.4. Экспорт

Вкладка «Оформление» — заполните организацию, автора, дату, город. Затем «Экспорт» → PDF / DOCX / HTML. Подробнее см. раздел 8.

3.Данные и форматы

3.1. Схема записи

{
  region: string,    // название региона
  year: number,      // 1990–2100
  value: number,     // млрд кВт·ч, ≥ 0, ≤ 100000
  status: "факт" | "оценка" | "прогноз",
  note: string       // источник или примечание
}

3.2. Формат CSV

Разделитель ;, , или табуляция — определяется автоматически. Кодировка — UTF-8 (можно с BOM).

Регион;Год;Значение;Статус;Примечание
Кемеровская обл.;2019;34.5;факт;Отчёт Минэнерго 2019
Москва;2019;68.2;факт;Мосэнерго
Москва;2020;65.4;оценка;

3.3. Формат JSON

[
  {
    "region": "Кемеровская обл.",
    "year": 2019,
    "value": 34.5,
    "status": "факт",
    "note": "Отчёт Минэнерго"
  }
]

3.4. Единицы измерения

Внутренне всё хранится в млрд кВт·ч. При отображении можно переключать в млн кВт·ч или ТВт·ч (Настройки → Единица). Коэффициенты:

ВводДействие
млн кВт·ч÷ 1000
ГВт·ч÷ 1000
ТВт·ч× 1000

3.5. Статусы

  • факт — подтверждённое значение из официального источника.
  • оценка — экспертная или расчётная оценка, не подтверждённая документом.
  • прогноз — модельная экстраполяция.

4.Проверки при импорте

При загрузке данных выполняется автоматическая валидация. Строки с ошибками отклоняются с указанием номера строки.

ПроверкаРезультат
Год < 1990 или > 2100Ошибка, строка отклоняется
Значение < 0Ошибка, строка отклоняется
Значение > 100 000Ошибка, вероятная опечатка
Не указан регионОшибка
Дубликат (регион + год)Предупреждение, заменяется
Будущий год со статусом «факт»Предупреждение
Неизвестный регионДобавляется автоматически
Совет. Все ошибки и предупреждения логируются в терминале (вкладки «Ошибки» и «Предупреждения»). Можно скопировать и передать разработчику.

9.Работа офлайн

Платформа работает офлайн после первой загрузки, при условии что браузер закешировал библиотеки (Plotly, SheetJS, docx, JSZip). Ограничения офлайн-режима:

  • экспорт в PDF/DOCX работает (используют локальные данные);
  • кнопки «Открыть DeepSeek» — требуют интернет;
  • обновление библиотек — требует интернет.

Если библиотеки не загрузились при первом открытии — в верхней части платформы появится предупреждение с точным списком отсутствующих модулей и кнопкой «Повторить».

10.Поддержка и обратная связь

При обнаружении ошибки:

  1. Откройте F12 → вкладка Console.
  2. Скопируйте текст ошибки (первую красную строку) и стек.
  3. Опишите сценарий воспроизведения.
  4. Приложите фрагмент данных (CSV/JSON), если воспроизведение связано с конкретным набором.

Все действия и ошибки платформы логируются в терминале (вкладки «Журнал», «Ошибки», «Предупреждения»).
